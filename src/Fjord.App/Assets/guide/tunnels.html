Tunnels (port forwarding)

Use the database, admin page or PC behind a server as if it were on your own machine, through the SSH connection you already have.

The idea in one paragraph. Lots of things refuse connections from the internet on purpose: a database that only listens on the server itself, a router's admin page, a Windows PC inside a customer's network. But you can SSH into a machine there. A tunnel opens a port on your PC (say localhost:15432). Everything you send to it travels encrypted inside SSH, and the server passes it on to the real target. Nothing on their firewall needs to change, and the tunnel closes when you disconnect.

1Making one in Fjord

  1. Connect to the server, then click Tunnels in the session toolbar. A panel opens beside the terminal, so you can keep typing.
  2. Pick what you want to reach, e.g. PostgreSQL database or Remote Desktop to a Windows PC. Fjord fills in sensible ports and finds a free one on your PC.
  3. Adjust the address if needed. The text under the picture tells you in plain words what will happen.
  4. Save. The tunnel starts straight away, and its card tells you exactly what to type, or gives you an Open in browser / Remote Desktop button.

Tunnels are saved with the session. Those marked start automatically open every time you connect. You can also add them before connecting, in the session editor under Tunnels (port forwarding).

2The one rule to remember

The target address is as seen from the server, not from your PC. localhost means "the server itself". 192.168.1.10 means "the machine with that IP in the server's network".

3Examples

A database that only accepts local connections

This PClocalhost:15432
SSH
serverport 5432

Preset PostgreSQL database, address localhost. In DBeaver/pgAdmin connect to host localhost, port 15432, with the normal database user. MySQL/MariaDB works the same (3306). We use 15432 rather than 5432 so it doesn't clash with a database running on your own PC.

SQL Server on a back-office PC

Preset SQL Server database, address = the SQL Server machine's IP as seen from the server, port 1433. In SSMS the server name is localhost,11433, with a comma, which is SQL Server's way of writing a port. Named instances (PC\SQLEXPRESS) use a random port by default. Give the instance a fixed TCP port in SQL Server Configuration Manager → TCP/IP → IPAll first.

The admin page of a router, printer or payment terminal

Preset Web page on a device in their network, address 192.168.1.1, port 80 (or 443 for https, and pick https under Advanced → Open button). Click Open in browser. Some devices redirect to their own IP address. If the page "jumps away", use Browse through the server instead (below).

Remote Desktop to a Windows PC behind the server

Preset Remote Desktop to a Windows PC, address = the PC's IP, port 3389. Remote Desktop on the card opens mstsc to localhost:13389. Log in with the PC's Windows account as usual.

Web UIs on your own server (Docker, Portainer, Radarr…)

Preset Web page on the server, address localhost, port = the app's port (Portainer 9000, Radarr 7878, Sonarr 8989, Jellyfin 8096…). Handy for containers published as 127.0.0.1:9000:9000 on purpose.

Preset Browse through the server. Then in Firefox: Settings → search "proxy" → Manual proxy configuration → SOCKS Host localhost, Port 1080, SOCKS v5, and tick Proxy DNS when using SOCKS v5. Every internal page now works, including ones that only allow the customer's IP. Firefox has its own proxy setting, so your other browsers are unaffected. Set it back to "No proxy" when done.

Let the server reach something on your PC (reverse tunnel)

serverlocalhost:8080
SSH
This PCport 3000

Preset Share something on my PC with the server. You're running a test API on your PC at port 3000. On the server, curl http://localhost:8080 reaches it. Useful for webhooks or letting a POS box talk to a development build.

4When it doesn't work

Fjord saysWhat to do
Port … on this PC is already in useAnother program or tunnel has it. Click Pick a free port in the tunnel editor.
… couldn't reach 192.168.1.10:5432The tunnel is up, but the server can't reach the target. Check the IP from the server: nc -zv 192.168.1.10 5432. Is the service running? Does it listen on that address (a database listening only on 127.0.0.1 must be reached with address localhost)?
… doesn't allow port forwardingThe server has AllowTcpForwarding no in /etc/ssh/sshd_config. Change it to yes and reload sshd, or ask the admin.
… refused to open port … (reverse tunnel)The port is taken on the server, or is below 1024. Try another port.
Browser shows "connection reset"Often http vs https: try the other one (Advanced → Open button), or port 443.

Only TCP can be tunnelled. UDP services (DNS, some VoIP, game servers) won't work.

5Good to know

  • Only you can use it. Tunnels listen on localhost, so other computers on your network can't use them. Advanced → Let other computers use this tunnel changes that. Use it sparingly, because anyone on your network then gets a way into the customer's side.
  • Tunnels live and die with the session. Disconnect, and they close. Reconnect, and the auto-start ones come back.
  • You're using the customer's network. Treat a tunnel like being on site: only reach what you're allowed to.

Same thing on the command line

For reference: Fjord's three tunnel types are OpenSSH's -L, -R and -D.

ssh -L 15432:localhost:5432 kim@server       # Local:   this PC :15432 → server's own :5432
ssh -L 13389:192.168.1.50:3389 kim@server    # Local:   this PC :13389 → 192.168.1.50:3389 via server
ssh -R 8080:localhost:3000 kim@server        # Remote:  server :8080 → this PC :3000
ssh -D 1080 kim@server                       # Dynamic: SOCKS proxy on this PC :1080
